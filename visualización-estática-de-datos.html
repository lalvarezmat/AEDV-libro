4.1 La gramática de los gráficos

La visualización de una colección variada de datos interrelacionados requiere organizar con claridad los distintos elementos que componen un gráfico. Para facilitar esta tarea se define una gramática (véase [Wil05], [Wi10]) en la que un gráfico es el resultado de combinar los siguientes elementos, organizados en capas:

Elementos de la gramática de los gráficos (ggplot2)

  • La tabla de datos y la declaración de los elementos de la tabla que intervienen en el gráfico.
  • Las capas con los atributos geométricos: histogramas, diagramas de caja, gráficos de líneas, estadísticos, ajustes de posición, etc.
  • Una escala por cada objeto geométrico incluido. La escala incluye el rango de valores utilizados y posibles transformaciones previas de los datos (por ejemplo, aplicar un logaritmo).
  • Un sistema de coordenadas. El más habitual, y el que se usa por defecto, es el cartesiano (ejes ortogonales X e Y), pero puede haber otros como, por ejemplo, el polar (gráficos circulares).
  • Especificaciones sobre la inclusión de múltiples gráficos (facets) combinando subconjuntos de los datos.
  • Opciones de formato y diseño de la salida.

Esta organización constituye una abstracción del proceso de creación gráfica que resulta muy potente: permite generar, con un código compacto y uniforme, todo tipo de gráficos complejos. La librería que implementa esta gramática en R es ggplot2, y su función principal ggplot. Como referencia rápida puede consultarse la ficha resumen de visualización de datos.

4.2 Anatomía de un ggplot: construcción por capas

Antes de recorrer los distintos tipos de gráfico, conviene ver cómo se construye un ggplot capa a capa, ya que todos los ejemplos posteriores siguen el mismo patrón. Partimos de los datos y vamos añadiendo elementos con el operador +: primero la declaración de la tabla y las variables (aes), después el objeto geométrico (geom_*), luego las escalas (scale_*) y, finalmente, los títulos y el tema. La siguiente figura muestra las cuatro etapas sobre un mismo gráfico:

# capa 1: datos + aes
p1 <- owid_country |>
  ggplot(aes(x = gdp_per_capit, y = life_expectancy)) +
  labs(title = "1. Datos + aes")

# capa 2: + geom_point
p2 <- p1 +
  geom_point(color = "steelblue") +
  labs(title = "2. + geom_point")

# capa 3: + escala log
p3 <- p2 +
  scale_x_continuous(transform = 'log2') +
  labs(title = "3. + scale (log)")

# capa 4: + títulos y tema
p4 <- p3 +
  labs(title = "4. + títulos y tema",
       x = "PIB per cápita (log)", y = "Esperanza de vida") +
  theme_bw()

wrap_plots(p1, p2, p3, p4, ncol = 2, nrow = 2) # combinamos las 4 capas

Figure 4.1: Construcción de un gráfico por capas: (1) lienzo con aes, (2) + geom_point, (3) + escala logarítmica, (4) + títulos y tema

Este esquema mental —datos → aes → geom → scale → theme/labs— es la clave para leer y escribir cualquier gráfico de ggplot2.

4.3 Diagramas de barras

A continuación se construye, usando ggplot, un diagrama de barras con la población mundial organizada por continentes. El gráfico se genera mediante la llamada a ggplot y la adición de una única capa producida por geom_col. Para añadir capas nuevas al gráfico se utiliza el operador +.

geom_col() frente a geom_bar(stat = "identity")

Cuando ya tenemos los valores calculados (por ejemplo tras un summarise), usamos geom_col() que toma los valores directamente del tibble. Es equivalente a geom_bar(stat = "identity") pero más conciso. En cambio, geom_bar() sin argumentos cuenta automáticamente las ocurrencias de cada categoría, lo cual es útil cuando queremos contar cuántos registros hay por grupo sin hacer un summarise previo.

owid_country |>  # países OWID
  group_by(continent)  |> # agrupamos por continente
  summarise(population=sum(population)) |> # sumamos población
  ggplot(aes(x=continent,y=population,fill=continent)) + # color por continente
    geom_col() + # barras
    theme(legend.position = "none") # sin leyenda

Figure 4.2: Diagrama de barras usando geom_col

la instrucción fill=continent se utiliza para asignar colores de forma automática a las barras. Al final del capítulo se verán en detalle estas cuestiones de diseño.

Sobre la leyenda

Por defecto, cuando usamos la opción fill en el aes, las barras se colorean y sale una leyenda a la derecha con información. Como regla general solo mantendremos la leyenda cuando aporta algo. En este caso la leyenda consiste en la lista de continentes con colores, que no aporta nada porque los nombres de los continentes ya aparecen en el eje x. Para suprimir la leyenda usamos la instrucción theme(legend.position = "none")

Por defecto, las barras se ordenan por orden alfabético. Con frecuencia queremos que las barras nos salgan ordenadas en función del valor mostrado. Para ello podemos ordenar previamente el tibble y después convertimos la variable a factor para fijar como orden el de la tabla ordenada (al ordenar una variable factor se ordena en función del nº asignado a cada etiqueta (level) del vector, no por el nombre vinculado).

owid_country |>  # países OWID
  group_by(continent)  |> # agrupamos por continente
  summarise(population=sum(population)) |> # sumamos población
  arrange(population) |> # ordenamos de menor a mayor
  mutate(continent= factor(continent, levels = continent)) |> # fijamos ese orden como factor
  ggplot(aes(x=continent,y=population,fill=continent)) + # color por continente
    geom_col() + # barras
    theme(legend.position = "none") # sin leyenda

Figure 4.3: Diagrama de barras usando geom_col con orden personalizado

4.4 Diagramas de barras agrupadas

Vamos a dibujar un diagrama de barras apiladas usando la media, por continentes, del porcentaje de hombres fumadores y de mujeres fumadoras.

A continuación vamos a representar el mismo gráfico con barras horizontales y “en espejo”, es decir, la línea vertical central representa el nivel cero y una variable se mueve hacia la derecha y otra hacia la izquierda. Para hacer esto tenemos que usar el truco de asignar un valor negativo a la variable que queremos que salga por la izquierda. Para que los valores del eje no salgan negativos se ponen en valor absoluto con la instrucción scale_y_continuous(labels= abs).

  summarise( # medias de fumadores por sexo
    male=mean(na.omit(male_smokers)),
    female=-mean(na.omit(female_smokers))) |> # signo negativo para el lado izquierdo
  pivot_longer(male:female, names_to = "sex", values_to = "smokers") |> # formato largo
  ggplot(aes(x=continent,y=smokers,fill=sex)) + # color por sexo
    geom_col() + # barras
    coord_flip() + # giramos 90 grados
    scale_y_continuous(labels= abs) # eje en valor absoluto

4.5 Gráficos circulares

Cuando el número de datos es pequeño, una manera eficaz de visualizar la relación entre los datos es utilizar los conocidos diagramas circulares (pie charts). En el siguiente ejemplo se muestra cómo construir uno usando la población mundial agrupada por continentes:

owid_country |>  # países OWID
  group_by(continent)  |> # agrupamos por continente
  summarise(population=sum(population)) |> # sumamos población
  mutate(labels = scales::percent(population/sum(population))) |> # % de cada continente
  ggplot(aes(x="",y=population,fill=continent)) + # una sola barra, sin eje x
    geom_col() + # barra apilada
    geom_text(aes(x=1.6,label = labels),position = position_stack(vjust = 0.5)) + # etiquetas con %
    coord_polar(theta = "y") # la enrollamos en círculo

Figure 4.7: Gráfico circular usando geom_col

Limitaciones de los gráficos circulares

Los estudios de percepción visual (Cleveland & McGill, 1984) muestran que el ojo humano compara longitudes con más precisión que ángulos o áreas. Por ello, los gráficos circulares son difíciles de interpretar cuando hay más de 5-6 categorías o cuando las proporciones son similares. En la mayoría de los casos, un diagrama de barras permite una comparación más precisa. Los gráficos circulares son útiles principalmente cuando se quiere resaltar que las partes suman un todo (100%) y las categorías son pocas y con proporciones claramente diferentes.

Cuando hay muchas categorías una buena idea es agregar los valores más pequeños en un solo valor (que podemos llamar “Otros”), usando, por ejemplo, el principio de Pareto. En el siguiente ejemplo aplicamos esta estrategia a las emisiones GHG por países (2024): conservamos los países que forman el 60% acumulado del total y agrupamos el resto en “Otros”:

read.xlsx('https://ctim.es/AEDV/data/EDGAR_GHG_Total_Emisiones_Paises.xlsx') |> # emisiones GHG
  as_tibble() |> # convertimos a tibble
  select(Country, `2024`) |> # país y emisiones de 2024
  rename(GHG = `2024`) |> # renombramos la columna
  mutate(pais = if_else(GHG >= aedv_pareto_value(GHG, 0.60), Country, "Otros")) |> # 60% acumulado
  group_by(pais) |> # agrupamos (incluye "Otros")
  summarise(GHG = sum(GHG)) |> # sumamos emisiones
  mutate(porc = scales::percent(GHG / sum(GHG), accuracy = 0.1)) |> # % de cada país
  ggplot(aes(x = "", y = GHG, fill = reorder(pais, -GHG))) + # color ordenado por GHG
    geom_col() + # barra apilada
    geom_text(aes(x = 1.6, label = porc), position = position_stack(vjust = 0.5), check_overlap = TRUE) + # etiquetas
    coord_polar(theta = "y") + # la enrollamos en círculo
    labs(fill = "País") + # título leyenda
    theme_void() # sin ejes ni fondo

4.8 Diagramas de cajas (box-plots)

Los diagramas de cajas son una herramienta muy potente para ilustrar la diferencia entre diferentes distribuciones. Los diagramas de cajas verticales contienen la siguiente información

  • \(Q_1\) : la base del rectángulo corresponde al cuartil 1 (percentil 25%).

  • \(Q_2\) : la línea central del rectángulo corresponde al cuartil 2 (percentil 50%, la mediana).

  • \(Q_3\) : la altura del rectángulo corresponde al cuartil 3 (percentil 75%).

  • Para dibujar las líneas por arriba y debajo se utiliza el valor \(IQR=Q_3-Q_1\).

  • La línea inferior se sitúa en el dato más pequeño que no baja de \(Q_1 - 1.5IQR\).

  • La línea superior se sitúa en el dato más grande que no supera \(Q_3 + 1.5IQR\).

  • Además se dibujan, en forma de puntos, los valores de los datos que quedan por debajo y por encima del box-plot. Estos valores se consideran “outliers” (valores fuera del rango esperado).

owid_country |> # países OWID
  ggplot(aes(x=continent,y=gdp_per_capit,fill=continent)) + # PIB por continente
    geom_boxplot() + # cajas
    theme(legend.position = "none") # sin leyenda

Figure 4.15: Diagrama de cajas usando geom_boxplot

La función facet_wrap agrupa la tabla por una variable y en una cuadrícula organiza de forma separada el gráfico de cada grupo. La función facet_grid hace lo mismo pero agrupando por dos variables que además determinan los ejes de la cuadrícula.

Veamos primero facet_wrap con los datos anuales de turistas nacionales y extranjeros por isla (ISTAC): un panel por isla (NAME) y, dentro de cada panel, las dos series de INDICATOR superpuestas con color.

  filter(nchar(TIME) == 4) |> # solo datos anuales
  mutate(anyo = as.integer(TIME)) |> # año numérico
  ggplot(aes(x = anyo, y = VALUE, color = INDICATOR)) + # color = indicador
    geom_line() + # líneas
    facet_wrap(~ NAME, scales = "free_y") + # un panel por isla, escala libre
    scale_y_continuous(labels = scales::label_scientific()) + # notación científica eje y
    labs(x = "Año", y = "Turistas", color = "Indicador") + # etiquetas
    theme(legend.position = "bottom") # leyenda abajo

Con scales = "free_y" cada uno de los 6 paneles calcula su propio rango vertical, así que se aprecia bien la evolución tanto en Canarias (más de 15 millones de turistas extranjeros al año) como en La Palma (apenas 250.000).

facet_grid permite combinar dos variables de agrupación a la vez, una por filas y otra por columnas. Repetimos el ejemplo cruzando INDICATOR (filas) y NAME (columnas):

readRDS(url("https://ctim.es/AEDV/data/ISTAC_TURISTAS.rds")) |> # leemos los datos
  filter(nchar(TIME) == 4) |> # solo datos anuales
  mutate(anyo = as.integer(TIME)) |> # año numérico
  ggplot(aes(x = anyo, y = VALUE)) + # sin color: ya separa por panel
    geom_line() + # líneas
    facet_grid(INDICATOR ~ NAME, scales = "free_y") + # filas = indicador, columnas = isla
    scale_y_continuous(labels = scales::label_scientific()) + # notación científica eje y
    labs(x = "Año", y = "Turistas") + # etiquetas
    theme(axis.text.x = element_text(angle = 45, hjust = 1)) # ticks inclinados

Figure 4.24: Turistas nacionales y extranjeros por isla (datos anuales), combinando INDICATOR y NAME con facet_grid y scales = 'free_y'. Fuente: ISTAC.

scales = "free_y" no funciona igual en facet_grid que en facet_wrap

En facet_grid, scales = "free_y" libera el eje por fila, no panel a panel: todas las columnas de una misma fila comparten el mismo rango vertical, porque facet_grid mantiene la cuadrícula alineada por filas y columnas. Por eso islas pequeñas como La Palma o Fuerteventura salen casi planas en el gráfico anterior —su escala real queda aplastada por la de Canarias, que comparte fila con ellas—, aunque su forma es la misma que en el facet_wrap de arriba, donde cada panel sí es independiente. Si se necesita cruzar dos variables de agrupación y, a la vez, una escala libre por panel, se le pueden pasar las dos a facet_wrap (p. ej. facet_wrap(~ INDICATOR + NAME, scales = "free_y")), a costa de perder la disposición en cuadrícula estricta de facet_grid.

Tal y como apunta la nota anterior, facet_wrap admite pasarle dos variables para agrupar. Otra forma es generar un atributo combinado con las dos variables. Para hacerlo, primero para que la etiqueta de cada panel (isla + indicador) no desborde la franja del título, la acortamos antes a mano en vez de usar el nombre completo del indicador (TURISTAS_NACIONALES/TURISTAS_EXTRANJEROS):

readRDS(url("https://ctim.es/AEDV/data/ISTAC_TURISTAS.rds")) |> # leemos los datos
  filter(nchar(TIME) == 4) |> # solo datos anuales
  mutate(
    anyo = as.integer(TIME), # año numérico
    indicador_corto = if_else(INDICATOR == "TURISTAS_NACIONALES", "Nac.", "Ext."), # versión corta
    grupo = paste(NAME, indicador_corto) # isla + indicador en un solo atributo
  ) |>
  ggplot(aes(x = anyo, y = VALUE)) +
    geom_line() + # líneas
    facet_wrap(~ grupo, scales = "free_y") + # un panel por combinación
    scale_y_continuous(labels = scales::label_scientific()) + # notación científica eje y
    labs(x = "Año", y = "Turistas") + # etiquetas
    theme(axis.text.x = element_text(angle = 45, hjust = 1), # ticks inclinados
          strip.text = element_text(size = 8)) # letra más pequeña en el título

Figure 4.25: Turistas por isla e indicador (datos anuales) usando facet_wrap sobre la combinación NAME/INDICATOR, con escala libre panel a panel. Fuente: ISTAC.

4.13 Doble eje vertical

En ocasiones, queremos comparar en la misma gráfica de línea dos variables de magnitudes muy distintas, para ello usamos un doble eje vertical, uno por la izquierda y otro por la derecha. Veamos un ejemplo comparando la incidencia diaria de casos (nº de infectados registrados) y los fallecidos por la COVID-19 en Francia. Para construir este tipo de gráfico usamos la función aedv_doble_eje() del fichero utilidades.R, que reescala la segunda variable al rango de la primera para poder superponerlas y configura el eje de la derecha para que deshaga esa escala y sus valores se lean en su unidad real.

Generación del gráfico con doble eje vertical

data <- owid_covid |>
  filter(iso_code=="FRA") |> # solo Francia
  mutate(date=as.Date(date))  |> # date a formato fecha
  select(fecha=date,fallecidos=new_deaths_restored_EpiInvert,incidencia=new_cases_restored_EpiInvert) # 3 columnas

aedv_doble_eje(data,"fecha","incidencia","red","fallecidos","blue") # eje izq. incidencia, eje der. fallecidos

Figure 4.27: Gráfico de líneas con doble eje vertical

El doble eje vertical, con precaución

En el ejemplo anterior el doble eje funciona muy bien, porque permite observar cómo evolucionó la incidencia registrada frente a los fallecidos: se aprecian los picos de incidencia seguidos de picos de fallecimientos y cómo, según avanza la pandemia, la altura de los picos de fallecimientos disminuye mucho respecto a la de incidencia.

Sin embargo, en general, este tipo de gráfico puede resultar engañoso. Al poder elegir libremente la escala de cada eje, dos series pueden parecer relacionadas sin estarlo: basta con estirar o encoger uno de los ejes para que las curvas se superpongan o se separen a voluntad. Por eso conviene conocer las dos alternativas habituales para comparar dos series de magnitudes distintas:

  1. Normalizar ambas variables a una escala común (por ejemplo, dividiendo cada una por su máximo) y dibujarlas con un solo eje vertical. Se pierde el valor real de las variables, pero la comparación de las formas es honesta.
  2. Dibujar las dos series en gráficos separados y apilados, uno encima del otro compartiendo el eje temporal (con el operador / de patchwork, que veremos en la sección de combinación de gráficos). La comparación resulta menos inmediata, pero cada serie conserva su escala real.

Nota crítica sobre las nubes de palabras

Al igual que ocurría con los gráficos circulares, las nubes de palabras son visualmente atractivas pero poco precisas para comparar cantidades: el tamaño percibido de una palabra depende no solo del valor que codifica sino también de su longitud (un país de nombre largo parece “pesar” más), y comparar tamaños de texto es perceptualmente más difícil que comparar longitudes de barras. La literatura actual de visualización (Wilke, entre las referencias de este capítulo) las desaconseja cuando el objetivo es la comparación cuantitativa. Su uso legítimo es decorativo o de impacto (una portada, una diapositiva inicial); para comparar valores con precisión, un diagrama de barras ordenado es siempre superior.

4.18 Colores

A la hora de presentar de manera eficiente y atractiva nuestro análisis de datos, es muy importante prestar atención a los elementos de diseño estético. En las secciones finales de este capítulo veremos cuestiones relacionadas con este aspecto, empezando por la gestión de los colores. En la gran mayoría de los gráficos de ejemplos que se muestran en este libro no se incluyen estos elementos estéticos, no porque no se les considere importante, sino para simplificar la presentación y poner énfasis en las cuestiones técnicas de los elementos geométricos. Sin embargo, todos estos gráficos son estéticamente mejorables usando las herramientas que se muestran en las secciones que siguen.

Los colores son un elemento de diseño muy importante en los gráficos. Hay varias formas diferentes de definir un color. Por ejemplo, podemos definir un color utilizando su nombre o su código HEX. Podemos distinguir 3 tipos de paletas :

  • Paletas de un solo color con luminosidad decreciente : el color se mantiene pero disminuye su luminosidad a lo largo de la paleta.

Ampliar el número de colores de una paleta divergente

Como vemos, el máximo número de colores que ofrecen las paletas divergentes de RColorBrewer es 12. Si necesitamos dibujar más objetos hay que ampliar la paleta, y aquí conviene evitar un error muy extendido: no interpolar una paleta divergente. La interpolación (colorRampPalette) construye los colores intermedios recorriendo el camino que va de uno a otro, y eso tiene sentido en una paleta secuencial, donde los colores están ordenados; pero en una divergente los colores no guardan ningún orden entre sí, así que interpolar genera tonos intermedios muy parecidos entre ellos, que es justo lo contrario de lo que buscamos.

Podemos comprobarlo midiendo la distancia perceptual mínima entre los colores de una paleta, es decir, cuánto se diferencian a la vista los dos colores más parecidos que contiene. Se calcula pasando los colores al espacio CIE Lab, diseñado para que las distancias se correspondan con las diferencias que percibe el ojo humano; por debajo de un valor de unas 2,3 unidades, dos colores resultan prácticamente indistinguibles:

# distancia perceptual mínima entre colores (espacio CIE Lab)
distancia_minima <- function(colores){
  lab <- t(apply(t(col2rgb(colores)/255), 1, function(x) # a espacio Lab
    convertColor(matrix(x, nrow = 1), from = "sRGB", to = "Lab")))
  d <- as.matrix(dist(lab)) # distancias entre todos los pares
  diag(d) <- Inf # ignoramos color consigo mismo
  min(d) # el par más parecido
}

La paleta interpolada queda muy por debajo del umbral de percepción: contiene colores que el ojo no distingue, de modo que el gráfico deja de cumplir su función.

Conviene detenerse en la comparación entre las dos alternativas, porque enseña a no fiarse de un único número. scales::hue_pal() —la función que ggplot2 usa por defecto, incluida en tidyverse— reparte los colores uniformemente por el círculo de tonos y multiplica por cinco la distancia mínima de la paleta interpolada. Y, sin embargo, con 20 categorías el resultado sigue sin ser bueno: como mantiene constantes la luminosidad y la saturación y solo hace girar el tono, los veinte colores se perciben como un degradado de arcoíris en el que cada barra se parece a sus vecinas. La distancia mínima mide el par más parecido de toda la paleta, pero no capta que los colores estén ordenados formando un continuo.

Por eso usaremos Polychrome::createPalette(), que genera los colores buscando explícitamente que estén lo más separados posible en las tres dimensiones del espacio perceptual —tono, luminosidad y saturación—, partiendo de unos colores semilla. El precio es que los colores resultantes son más saturados y forman un conjunto menos armonioso que Set3; a cambio, cada categoría queda inconfundible, que es exactamente lo que se le pide a una paleta divergente.

Nótese que las barras no se ordenan por población, sino alfabéticamente. Ordenarlas por magnitud sugeriría visualmente una escala creciente, y esa es la lectura que corresponde a una paleta secuencial, no a una divergente: aquí el color solo sirve para distinguir países, no para codificar ninguna cantidad.

El color se asigna con scale_fill_manual, no dentro de aes()

Un error fácil de cometer es pasar el vector de colores directamente a la estética, escribiendo aes(fill = mi_paleta). Eso no aplica la paleta: aes() espera el nombre de una variable de los datos con la que agrupar, así que ggplot interpreta ese vector de códigos de color como si fuera una variable categórica más y le asigna… sus propios colores por defecto. El gráfico se dibuja sin error, pero con una paleta distinta de la que se pretendía.

La forma correcta es la del ejemplo anterior: mapear la estética a la variable (aes(fill = location)) y declarar los colores en una escala aparte, con scale_fill_manual(values = ...).

coord_cartesian vs. ylim para hacer zoom

Cuando queremos hacer zoom en una región del gráfico, es importante distinguir entre dos métodos:

  • scale_y_continuous(limits=...) o ylim() eliminan los datos fuera del rango antes de calcular estadísticas. Esto afecta a funciones como geom_smooth que recalculan la regresión solo con los datos visibles.

  • coord_cartesian(ylim=...) hace zoom sin eliminar datos, solo ajusta la ventana de visualización. Las estadísticas se calculan con todos los datos.

4.21 Una tabla pulida de referencia: gt

El mismo criterio de acabado profesional se aplica a las tablas. A lo largo del libro usamos knitr::kable(), que es perfectamente adecuado para tablas simples (y en el capítulo de visualización dinámica veremos DT para tablas interactivas). Cuando una tabla es una pieza central de un informe, el estándar actual para tablas estáticas con calidad de publicación es la librería gt, desarrollada por el equipo de Posit. Su filosofía es análoga a la de ggplot2: la tabla se construye por capas (cabecera, etiquetas de columnas, formato de números, nota de fuente):

tabla <- owid_country |>

  gt() |> # tabla gt
  tab_header( # título y subtítulo
    title = "Los 10 países con mayor esperanza de vida",
    subtitle = "Indicadores básicos por país"
  ) |>
  cols_label( # renombramos las columnas
    location = "País",

  ) |>
  fmt_number(columns = life_expectancy, decimals = 1) |> # 1 decimal
  fmt_number(columns = gdp_per_capit, decimals = 0) |> # sin decimales

Color condicional en gt: la filosofía de capas

La tabla tabla que construimos en la sección anterior no queda cerrada al mostrarla: es un objeto vivo al que se le pueden seguir encadenando capas, igual que a un ggplot. Vamos a añadirle dos capas más con data_color(), una por cada columna numérica, para colorear cada celda según su valor con un degradado:

tabla |>
  data_color(
    columns = life_expectancy,
    palette = "Blues" # degradado de un solo color: cuanto más oscuro, mayor esperanza de vida
  ) |>
  data_color(
    columns = gdp_per_capit,
    palette = "Oranges" # degradado INDEPENDIENTE para la otra columna numérica
  )

Las dos llamadas a data_color() son capas independientes: cada una calcula su degradado a partir del rango de valores de su propia columna, sin que una interfiera con la otra ni con las capas anteriores (cabecera, etiquetas, formato de los números). Es la misma filosofía de ggplot2 —el objeto separa los datos de las instrucciones de construcción, y cada función añadida se limita a apilar una instrucción más—, aplicada aquí a una tabla en lugar de a un gráfico.

4.22 Exportar gráficos con ggsave

Para guardar un gráfico en un fichero usamos la función ggsave. Esta función guarda, por defecto, el último gráfico generado, o el gráfico que le pasemos como argumento. Soporta múltiples formatos: PNG (para web), PDF (para publicaciones), SVG (vectorial escalable), JPEG, TIFF, entre otros:

# Guardar el último gráfico generado
ggsave("mi_grafico.png", width = 8, height = 5, dpi = 300)

# Guardar en PDF (ideal para publicaciones, escalable sin pérdida)
ggsave("mi_grafico.pdf", width = 8, height = 5)

# Guardar un gráfico almacenado en una variable
p <- ggplot(owid_country, aes(x = gdp_per_capit, y = life_expectancy)) + geom_point()
ggsave("dispersion.png", plot = p, width = 8, height = 5, dpi = 300)

Los parámetros width y height controlan las dimensiones del gráfico en pulgadas y dpi la resolución (300 dpi es estándar para impresión, 72-150 dpi para pantalla). Para presentaciones o informes donde los gráficos se van a ampliar, es recomendable usar formatos vectoriales como PDF o SVG.
