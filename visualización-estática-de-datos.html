En este curso se concede gran importancia a la visualización de datos. En este capítulo se presenta la visualización estática, que corresponde al tipo habitual de gráfico donde el usuario no interacciona con la representación. Como se verá, con muy pocas líneas de código es posible crear gráficos complejos y visualmente atractivos gracias a una estructura común e independiente del tipo de contenido: la denominada gramática de los gráficos, que se introduce a continuación.

4.1 La gramática de los gráficos

La visualización de una colección variada de datos interrelacionados requiere organizar con claridad los distintos elementos que componen un gráfico. Para facilitar esta tarea se define una gramática (véase [Wi10]) en la que un gráfico es el resultado de combinar los siguientes elementos, organizados en capas:

Elementos de la gramática de los gráficos (ggplot2)

  • La tabla de datos y la declaración de los elementos de la tabla que intervienen en el gráfico.
  • Las capas con los atributos geométricos: histogramas, diagramas de caja, gráficos de líneas, estadísticos, ajustes de posición, etc.
  • Una escala por cada objeto geométrico incluido.
  • Un sistema de coordenadas.
  • Especificaciones sobre la inclusión de múltiples gráficos (facets) combinando subconjuntos de los datos.
  • Opciones de formato y diseño de la salida.

Esta organización constituye una abstracción del proceso de creación gráfica que resulta muy potente: permite generar, con un código compacto y uniforme, todo tipo de gráficos complejos. La librería que implementa esta gramática en R es ggplot2, y su función principal ggplot. Como referencia rápida puede consultarse la ficha resumen de visualización de datos.

Guía de selección de gráficos

Antes de empezar a crear gráficos, es importante saber elegir el tipo de gráfico adecuado en función de la pregunta que queremos responder con los datos. La siguiente tabla sirve como guía de referencia:

Table 4.1: Guía de selección de gráficos según el objetivo del análisis

4.2 Anatomía de un ggplot: construcción por capas

Antes de recorrer los distintos tipos de gráfico, conviene ver cómo se construye un ggplot capa a capa, ya que todos los ejemplos posteriores siguen el mismo patrón. Partimos de los datos y vamos añadiendo elementos con el operador +: primero la declaración de la tabla y las variables (aes), después el objeto geométrico (geom_*), luego las escalas (scale_*) y, finalmente, los títulos y el tema. La siguiente figura muestra las cuatro etapas sobre un mismo gráfico:

# Capa 1: datos + aes (define los ejes, pero aún no dibuja nada)
p1 <- owid_country |>
  ggplot(aes(x = gdp_per_capit, y = life_expectancy)) +
  labs(title = "1. Datos + aes")

# Capa 2: se añade el objeto geométrico (los puntos)
p2 <- p1 +
  geom_point(color = "steelblue") +
  labs(title = "2. + geom_point")

# Capa 3: se añade una escala (eje x logarítmico)
p3 <- p2 +
  scale_x_continuous(transform = 'log2') +
  labs(title = "3. + scale (log)")

# Capa 4: se añaden títulos y un tema
p4 <- p3 +
  labs(title = "4. + títulos y tema",
       x = "PIB per cápita (log)", y = "Esperanza de vida") +
  theme_bw()

# Se dibujan las 4 capas en un gráfico combinado
wrap_plots(p1, p2, p3, p4, ncol = 2, nrow = 2)

Figure 4.1: Construcción de un gráfico por capas: (1) lienzo con aes, (2) + geom_point, (3) + escala logarítmica, (4) + títulos y tema

Este esquema mental —datos → aes → geom → scale → theme/labs— es la clave para leer y escribir cualquier gráfico de ggplot2.

4.3 Diagramas de barras

A continuación se construye, usando ggplot, un diagrama de barras con la población mundial organizada por continentes. El gráfico se genera mediante la llamada a ggplot y la adición de una única capa producida por geom_col. Para añadir capas nuevas al gráfico se utiliza el operador +.

geom_col() vs. geom_bar(stat = "identity"). Cuando ya tenemos los valores calculados (por ejemplo tras un summarise), usamos geom_col() que toma los valores directamente del tibble. Es equivalente a geom_bar(stat = "identity") pero más conciso. En cambio, geom_bar() sin argumentos cuenta automáticamente las ocurrencias de cada categoría, lo cual es útil cuando queremos contar cuántos registros hay por grupo sin hacer un summarise previo.

owid_country |>  
  group_by(continent)  |> 
  summarise(population=sum(population)) |>
  ggplot(aes(x=continent,y=population,fill=continent)) +
    geom_col() +
    theme(legend.position = "none")

Figure 4.2: Diagrama de barras usando geom_col

la instrucción fill=continent se utiliza para asignar colores de forma automática a las barras. Al final del capítulo se verán en detalle estas cuestiones de diseño.

Por defecto estos gráficos generan una leyenda a la derecha con información. Como regla general solo se pone una leyenda cuando aporta algo. En este caso la leyenda consiste en la lista de continentes con colores, que no aporta nada porque los nombres de los continentes ya aparecen en el eje x. Para suprimir la leyenda usamos la instrucción theme(legend.position = "none")

Por defecto, las barras se ordenan por orden alfabético. Con frecuencia queremos que las barras nos salgan ordenadas en función del valor mostrado. Para ello podemos ordenar previamente el tibble y después usar la función factor para fijar un orden personalizado que evite la ordenación automática.

owid_country |>  
  group_by(continent)  |> 
  summarise(population=sum(population)) |>
  arrange(population) |>
  mutate(continent= factor(continent, levels = continent)) |> 
  ggplot(aes(x=continent,y=population,fill=continent)) +
    geom_col() +
    theme(legend.position = "none")

Figure 4.3: Diagrama de barras usando geom_col con orden personalizado

4.4 Diagramas de barras agrupadas

Vamos a dibujar un diagrama de barras apiladas usando la media, por continentes, del porcentaje de hombres fumadores y de mujeres fumadoras.

owid_country |>  
  group_by(continent)  |> 
  summarise(
    male=mean(na.omit(male_smokers)),
    female=mean(na.omit(female_smokers))) |>
  pivot_longer(male:female, names_to = "sex", values_to = "smokers") |>  
  ggplot(aes(x=continent,y=smokers,fill=sex)) +
    geom_bar(stat = "identity")

Figure 4.4: Diagrama de barras apilado usando geom_bar

A continuación haremos lo mismo pero poniendo las barras una al lado de otra con la opción position="dodge".

owid_country |>  
  group_by(continent)  |> 
  summarise(
    male=mean(na.omit(male_smokers)),
    female=mean(na.omit(female_smokers))) |>
  pivot_longer(male:female, names_to = "sex", values_to = "smokers") |>  
  ggplot(aes(x=continent,y=smokers,fill=sex)) +
    geom_bar(position="dodge",stat = "identity")

Figure 4.5: Diagrama de barras alineadas usando geom_bar

A continuación vamos a representar el mismo gráfico con barras horizontales y “en espejo”, es decir, la línea vertical central representa el nivel cero y una variable se mueve hacia la derecha y otra hacia la izquierda. Para hacer esto tenemos que usar el truco de asignar un valor negativo a la variable que queremos que salga por la izquierda. Para que los valores del eje no salgan negativos se ponen en valor absoluto con la instrucción scale_y_continuous(labels= abs).

owid_country |>  
  group_by(continent)  |> 
  summarise(
    male=mean(na.omit(male_smokers)),
    female=-mean(na.omit(female_smokers))) |> # cambiamos el signo de esta variable 
  pivot_longer(male:female, names_to = "sex", values_to = "smokers") |>  
  ggplot(aes(x=continent,y=smokers,fill=sex)) +
    geom_col() +
    coord_flip() + # giramos el gráfico 90 grados 
    scale_y_continuous(labels= abs) # valores del eje en valor absoluto

Figure 4.6: Diagrama de barras horizontal para comparar 2 variables usando geom_col

4.5 Gráficos circulares

Cuando el número de datos es pequeño, una manera eficaz de visualizar la relación entre los datos es utilizar los conocidos diagramas circulares (pie charts). En el siguiente ejemplo se muestra cómo construir uno usando la población mundial agrupada por continentes:

owid_country |>  
  group_by(continent)  |> 
  summarise(population=sum(population)) |>
  mutate(labels = scales::percent(population/sum(population))) |>
  ggplot(aes(x="",y=population,fill=continent)) +
    geom_col() +
    geom_text(aes(x=1.6,label = labels),position = position_stack(vjust = 0.5)) + 
    coord_polar(theta = "y")

Figure 4.7: Gráfico circular usando geom_col

La función coord_polar se puede usar para transformar un gráfico de barras en un gráfico de sectores circulares. Veamos cómo queda el gráfico de barras apilado de la sección anterior al transformarlo en un gráfico de sectores circulares

owid_country |>  
  group_by(continent)  |> 
  summarise(
    male=mean(na.omit(male_smokers)),
    female=mean(na.omit(female_smokers))) |>
  pivot_longer(male:female, names_to = "sex", values_to = "smokers") |>  
  ggplot(aes(x=continent,y=smokers,fill=sex)) +
    geom_bar(stat = "identity",width = 1) +
    coord_polar(theta = "x")

Figure 4.8: Diagrama de barras apilado transformado en sectores circulares usando coord_polar

Limitaciones de los gráficos circulares. Los estudios de percepción visual (Cleveland & McGill, 1984) muestran que el ojo humano compara longitudes con más precisión que ángulos o áreas. Por ello, los gráficos circulares son difíciles de interpretar cuando hay más de 5-6 categorías o cuando las proporciones son similares. En la mayoría de los casos, un diagrama de barras permite una comparación más precisa. Los gráficos circulares son útiles principalmente cuando se quiere resaltar que las partes suman un todo (100%) y las categorías son pocas y con proporciones claramente diferentes.

Cuando hay muchas categorías una buena idea es agregar los valores más pequeños en un solo valor (que podemos llamar “Otros”), usando, por ejemplo, el principio de Pareto. En el siguiente ejemplo aplicamos esta estrategia a las emisiones GHG por países (2024): conservamos los países que forman el 60% acumulado del total y agrupamos el resto en “Otros”:

ParetoValue <- function(v, ParetoSignificancia) {
  x <- sort(v, decreasing = TRUE)
  x[which(cumsum(x) >= ParetoSignificancia * sum(x))[1]]
}

read.xlsx('https://ctim.es/AEDV/data/EDGAR_GHG_Total_Emisiones_Paises.xlsx') |>
  as_tibble() |>
  select(Country, `2024`) |>
  rename(GHG = `2024`) |>
  mutate(pais = if_else(GHG >= ParetoValue(GHG, 0.60), Country, "Otros")) |>
  group_by(pais) |>
  summarise(GHG = sum(GHG)) |>
  mutate(porc = scales::percent(GHG / sum(GHG), accuracy = 0.1)) |>
  ggplot(aes(x = "", y = GHG, fill = reorder(pais, -GHG))) +
    geom_col() +
    geom_text(aes(x = 1.6, label = porc), position = position_stack(vjust = 0.5), check_overlap = TRUE) +
    coord_polar(theta = "y") +
    labs(fill = "País") +
    theme_void()

Figure 4.9: Gráfico circular de emisiones GHG (2024). Los países que no alcanzan el 60% acumulado se agrupan en ‘Otros’ (principio de Pareto). Fuente: EDGAR.

4.6 Gráficos de donuts

Los gráficos de donuts son muy parecidos a los circulares dejando un hueco circular dentro del gráfico. Utilizaremos la variable hsize para fijar el tamaño del agujero.

hsize <- 2
owid_country |>  
  group_by(continent)  |> 
  summarise(population=sum(population)) |>
  mutate(labels = scales::percent(population/sum(population))) |>
  ggplot(aes(x=hsize,y=population,fill=continent)) +
    geom_col() +
    geom_text(aes(x=hsize + 0.1,label = labels),position = position_stack(vjust = 0.5)) + 
    coord_polar(theta = "y") +
    xlim(c(0.2, hsize + 0.5))

Figure 4.10: Gráfico de donuts usando geom_col

4.7 Histogramas

Vamos, a continuación, a dibujar un histograma del PIB por habitante en los diferentes países del mundo usando ggplot.

owid_country |> 
  ggplot(aes(x=gdp_per_capit)) + 
    geom_histogram()

Figure 4.11: Gráfico de histograma usando geom_histogram()

A continuación haremos lo mismo pero ajustando el histograma a una función de densidad de probabilidad.

owid_country |> 
  ggplot(aes(x=gdp_per_capit)) + 
    geom_histogram(aes(y=after_stat(density))) +
    geom_density(alpha=0.6)

Figure 4.12: Histograma y función de densidad con geom_histogram y geom_density

4.8 Diagramas de cajas (box-plots)

Los diagramas de cajas son una herramienta muy potente para ilustrar la diferencia entre diferentes distribuciones. Los diagramas de cajas verticales contienen la siguiente información

  • \(Q_1\) : la base del rectángulo corresponde al cuartil 1 (percentil 25%).

  • \(Q_2\) : la línea central del rectángulo corresponde al cuartil 2 (percentil 50%, la mediana).

  • \(Q_3\) : la altura del rectángulo corresponde al cuartil 3 (percentil 75%).

  • Para dibujar las líneas por arriba y debajo se utiliza el valor \(IQR=Q_3-Q_1\).

  • La línea inferior se sitúa en el dato más pequeño que no baja de \(Q_1 - 1.5IQR\).

  • La línea superior se sitúa en el dato más grande que no supera \(Q_3 + 1.5IQR\).

  • Además se dibujan, en forma de puntos, los valores de los datos que quedan por debajo y por encima del box-plot. Estos valores se consideran “outliers” (valores fuera del rango esperado).

owid_country |> 
  ggplot(aes(x=continent,y=gdp_per_capit,fill=continent)) + 
    geom_boxplot() +
    theme(legend.position = "none")

Figure 4.16: Diagrama de cajas usando geom_boxplot

Cuando el conjunto de valores no es muy grande se suelen dibujar los valores en forma de puntos para ilustrar mejor la distribución

owid_country |> 
  ggplot(aes(x=continent,y=gdp_per_capit,fill=continent)) +

Figure 4.17: Diagrama de cajas que incluye todos los valores como puntos, usando geom_jitter

4.13 Doble eje vertical

En ocasiones, queremos comparar en la misma gráfica de línea dos variables de magnitudes muy distintas, para ello usamos un doble eje vertical, uno por la izquierda y otro por la derecha. Veamos un ejemplo comparando la incidencia diaria de casos (nº de infectados registrados) y los fallecidos por la COVID-19 en Francia. Para facilitar la generación de este tipo de gráfico primero implementamos en una función la construcción del gráfico y después simplemente llamamos a dicha función:

DrawDualAxes <- function(
tb, # tibble con los datos 
namex, # string con el nombre de la variable del eje x en el tibble 
namey1, # string con el nombre de la variable del eje y en el tibble por la izquierda
color1, # string con el nombre del color para dibujar el eje  y por la izquierda
namey2, # string con el nombre de la variable del eje y en el tibble por la derecha
color2 # string con el nombre del color para dibujar el eje  y por la derecha
){      
  y1.min<-min(tb[[namey1]])
  y2.min<-min(tb[[namey2]])    
  m1<-(max(tb[[namey1]])-y1.min)/(max(tb[[namey2]])-y2.min)
  p <- tibble(
    x=tb[[namex]],
    y1=tb[[namey1]],
    y2=tb[[namey2]]
  )  |> ggplot(aes(x=x)) + 
  geom_line(aes(y = y1, color = color1)) + # dibujamos la primera variable 
  geom_line(aes(y = y1.min+(y2-y2.min)*m1), color=color2) + # dibujamos la segunda variable escalada
  #asignamos títulos a los ejes y creamos los valores del eje vertical por la derecha
  scale_y_continuous(name =namey1,sec.axis = sec_axis(~ (. - y1.min)/m1+y2.min, name=namey2)) +
  theme(
    axis.title.y = element_text(color =color1),
    axis.title.y.right = element_text(color = color2),
    legend.position="none"
 )
  return(p)
}

4.16 Mapas de calor

Un mapa de calor (Heatmap) es una tabla de valores numéricos donde las celdas tienen un color que varía de acuerdo con el valor numérico de la celda. Para ilustrar esta herramienta vamos a hacer un mapa de calor con los valores de algunos indicadores de los países de Europa almacenados en el tibble owid_country. Como en este caso los valores de los indicadores se mueven en rangos muy distintos los vamos a normalizar dividiéndolos por su máximo. De esta manera el valor 1 corresponde al país con mayor valor y en el resto de países el valor indica la proporción del valor del país con respecto al máximo.

En las siguientes instrucciones se filtra el tibble owid_country, se seleccionan los campos que intervienen en el mapa de calor y se normalizan

# Normalizamos cada columna numérica dividiéndola por su máximo.
# En lugar de un bucle, usamos mutate(across(...)) — coherente con el estilo tidyverse del curso.
sel_owid_country <- owid_country |>
  filter(continent=="Europe" & is.na(aged_65_older)==FALSE )  |>
  select(location,population:gdp_per_capit,hospital_beds_per_thousand, human_development_index) |>
  mutate(across(-location, ~ round(. / max(., na.rm = TRUE), 2)))

A continuación creamos el mapa de calor utilizando la paleta de colores YlOrRd. Previamente tenemos que modificar, usando pivot_longer, la organización del tibble para pasarlo al formato tidy data o largo que requiere ggplot

Nota crítica. Al igual que ocurría con los gráficos circulares, las nubes de palabras son visualmente atractivas pero poco precisas para comparar cantidades: el tamaño percibido de una palabra depende no solo del valor que codifica sino también de su longitud (un país de nombre largo parece “pesar” más), y comparar tamaños de texto es perceptualmente más difícil que comparar longitudes de barras. La literatura actual de visualización (Wilke, entre las referencias de este capítulo) las desaconseja cuando el objetivo es la comparación cuantitativa. Su uso legítimo es decorativo o de impacto (una portada, una diapositiva inicial); para comparar valores con precisión, un diagrama de barras ordenado es siempre superior.

4.18 Colores

A la hora de presentar de manera eficiente y atractiva nuestro análisis de datos, es muy importante prestar atención a los elementos de diseño estético. En las secciones finales de este capítulo veremos cuestiones relacionadas con este aspecto, empezando por la gestión de los colores. En la gran mayoría de los gráficos de ejemplos que se muestran en este libro no se incluyen estos elementos estéticos, no porque no se les considere importante, sino para simplificar la presentación y poner énfasis en las cuestiones técnicas de los elementos geométricos. Sin embargo, todos estos gráficos son estéticamente mejorables usando las herramientas que se muestran en las secciones que siguen.

Los colores son un elemento de diseño muy importante en los gráficos. Hay varias formas diferentes de definir un color. Por ejemplo, podemos definir un color utilizando su nombre o su código HEX. En r-charts.com se puede encontrar una detallada lista de colores con su nombre y código HEX. A continuación se muestra una selección de colores con sus nombres asociados.

Figure 4.33: Tabla con una selección de colores con sus nombre asociados

otra forma de definir los colores es a través de su nivel de rojo (R), verde (G), y azul (B), así como un valor alpha (opcional) que indica su transparencia cuando se superpone a otras figuras ya pintadas. Cada componente se mueve entre valores 0 y 1. Por ejemplo rgb(1.,0.,0.) sería el color rojo y rgb(0.,0.,1.,0.9) sería el color azul con una ligera transparencia.

A cada elemento geométrico dibujable de ggplot le podemos asignar colores utilizando los atributos color (color del objeto geométrico) y fill (color de relleno interior de la forma). Además, la asignación puede ser automática o manual. Veamos algunos ejemplos con un diagrama de barras

  theme(legend.position = "none")

Otra forma de definir colores es usando paletas. La librería RColorBrewer suministra las siguientes paletas de colores:

Figure 4.37: Paletas de colores de la librería RColorBrewer

Podemos distinguir 3 tipos de paletas :

  • Paletas de un solo color con luminosidad decreciente : el color se mantiene pero disminuye su luminosidad a lo largo de la paleta.

  • Paletas divergentes : la luminosidad y color no siguen un patrón progresivo.

  • Paletas con varios colores : la paleta empieza con un color oscuro que se va aclarando hasta llegar a la mitad de la tabla, después cambia de color y se va oscureciendo progresivamente.

Las paletas con colores progresivos son especialmente adecuadas cuando asociamos un color a un valor numérico, de tal forma que queremos que el color cambie progresivamente en función del valor numérico. Una aplicación de esto lo veremos en la siguiente sección donde se explicarán los heatmaps.

owid_country |>  
  group_by(continent)  |> 
  summarise(population=sum(population)) |>
  ggplot(aes(x=continent,y=population,fill=continent)) +
    geom_bar(stat = "identity") +
    scale_fill_brewer(palette = "Paired") +
  theme(legend.position = "none")

Figure 4.38: Diagrama de barras con colores usando scale_fill_brewer

Como vemos, el máximo número de colores que ofrecen las paletas de RColorBrewer es 12, si necesitamos dibujar más de 12 objetos, podemos extender la paleta de colores usando colorRampPalette. Además, para ello necesitamos también saber cuántos objetos necesitamos colorear en la gráfica. En el siguiente ejemplo necesitamos colorear 20 objetos y por tanto necesitamos 20 colores:

getPalette = colorRampPalette(brewer.pal(12, "Set3"))
NúmeroDeColores <- 20 
owid_country |>  
  arrange(population) |> 
  tail(20) |> 
  mutate(location=factor(location,levels=location)) |>
  ggplot(aes(x=location,y=population,fill=getPalette(NúmeroDeColores))) +
  geom_bar(stat = "identity") + 
  coord_flip() + 
  theme(legend.position="none")

Figure 4.39: Diagrama de barras con interpolación de colores brewer usando colorRampPalette

Escalas de color accesibles (viridis)

Un aspecto importante en la visualización profesional es la accesibilidad: aproximadamente el 8% de los hombres y el 0.5% de las mujeres tienen algún tipo de daltonismo. La familia de escalas viridis está diseñada para ser perceptualmente uniforme y legible por personas con deficiencias en la visión del color. Además, se imprime correctamente en blanco y negro:

owid_country |>
  ggplot(aes(x = gdp_per_capit, y = life_expectancy, color = continent)) +
    geom_point(size = 2) +
    scale_x_continuous(transform = 'log2') +
    scale_color_viridis_d() +  # _d para variables discretas, _c para continuas
    labs(x = "PIB per cápita (escala log)", y = "Esperanza de vida")

Figure 4.40: Diagrama de dispersión usando la escala de color viridis accesible para daltónicos

Las funciones scale_color_viridis_d() (para variables discretas) y scale_color_viridis_c() (para variables continuas) están incluidas en ggplot2 y no requieren librerías adicionales. Para rellenos se usan scale_fill_viridis_d() y scale_fill_viridis_c(). Se recomienda su uso siempre que el gráfico vaya a ser publicado o compartido con audiencias diversas.

4.19 Themes

El diseño general de la salida de un gráfico de ggplot se controla a través de la capa theme. Podemos modificar todos los atributos por defecto de diseño de salida usando diferentes themes. De hecho hay paquetes en R dedicados exclusivamente al diseño de themes. Para ilustrar esto con un ejemplo, utilizaremos el theme theme_bw en un gráfico :

owid_country |> 
  ggplot(aes(x=gdp_per_capit,y=life_expectancy,color=continent)) + 
    geom_point() +
    theme_bw() + 
    scale_x_continuous(transform = 'log2') + 
    labs(title="Distribución, por continentes, del PIB por habitante ",x="gdp_per_capit", y = "life_expectancy")

Figure 4.41: Usando el theme theme_bw

Además de definir un theme general para el gráfico, podemos controlar los atributos individuales del theme, añadiendo al gráfico una capa theme adicional. A continuación se muestran algunos atributos que se pueden configurar con la capa theme

owid_country |> 
  ggplot(aes(x=gdp_per_capit,y=life_expectancy,color=continent)) + 
    geom_point() +
    scale_x_continuous(transform = 'log2') + 
    theme(
      panel.background = element_rect( fill = "ivory", #color de fondo
                                      color = "black", # color del borde
                                      linewidth = 2), # grosor borde
      panel.grid = element_line( color = "blue", #color cuadrícula
                                 linewidth = 0.5, # grosor cuadrícula
                                 linetype = 2), # tipo línea
      axis.title.y = element_blank(), # quitar título eje y
      axis.text.x = element_text(angle = 45,hjust=1), # inclinar texto eje x
      legend.position="none", # quitar leyenda situada a la derecha 
      text = element_text(size = 20) # modifica el tamaño de la letra 
    )

Figure 4.42: Algunas opciones de theme

Si queremos modificar el tema por defecto en todo el documento podemos poner la siguiente instrucción al principio del documento

# el tema por defecto se fija a "theme_bw"
theme_set(theme_bw())

4.19.1 Diseño títulos y ejes

owid_country |> 
  ggplot(aes(x=gdp_per_capit,y=life_expectancy,color=continent)) + 
    geom_point() +
    labs( title = "Mi Título", 
          subtitle = "Mi Subtítulo", 
          x= "Título eje x", 
          y= "Título eje y"
    ) +
    scale_x_continuous(transform = 'log2', # función transformación eje x
                       n.breaks = 10, # número cortes eje x
                       ) +
    scale_y_continuous(n.breaks = 10) # número cortes eje y

coord_cartesian vs. ylim para hacer zoom

Cuando queremos hacer zoom en una región del gráfico, es importante distinguir entre dos métodos:

  • scale_y_continuous(limits=...) o ylim() eliminan los datos fuera del rango antes de calcular estadísticas. Esto afecta a funciones como geom_smooth que recalculan la regresión solo con los datos visibles.

  • coord_cartesian(ylim=...) hace zoom sin eliminar datos, solo ajusta la ventana de visualización. Las estadísticas se calculan con todos los datos.

p1 <- owid_country |>
  ggplot(aes(x = gdp_per_capit, y = life_expectancy)) +
  geom_point(alpha = 0.5) +
  geom_smooth(method = lm, se = FALSE, color = "red") +
  scale_x_continuous(transform = 'log2') +
  scale_y_continuous(limits = c(65, 85)) +
  labs(title = "scale_y_continuous (elimina datos)")

p2 <- owid_country |>
  ggplot(aes(x = gdp_per_capit, y = life_expectancy)) +
  geom_point(alpha = 0.5) +
  geom_smooth(method = lm, se = FALSE, color = "red") +
  scale_x_continuous(transform = 'log2') +
  coord_cartesian(ylim = c(65, 85)) +
  labs(title = "coord_cartesian (solo zoom)")

wrap_plots(p1, p2, ncol = 2)

Figure 4.43: Comparación entre ylim (izquierda, datos eliminados) y coord_cartesian (derecha, solo zoom)

Obsérvese cómo la recta de regresión cambia en el gráfico de la izquierda (porque se han eliminado los puntos fuera del rango al usar scale_y_continuous(limits=...)) mientras que en el de la derecha mantiene su pendiente original. En general, se recomienda usar coord_cartesian para hacer zoom.

4.20 Un gráfico pulido de referencia

La mayoría de los gráficos de este capítulo se han dejado deliberadamente sin cuidar la estética, para centrar la atención en el elemento geométrico. A modo de contraste, mostramos aquí cómo queda un gráfico cuando se le aplican todas las herramientas de diseño vistas (título y subtítulo informativos, etiquetas de ejes, escala logarítmica, color con significado, etiquetas de puntos sin solapamiento, tema y anotación de la fuente). 4.21 Una tabla pulida de referencia: gt

El mismo criterio de acabado profesional se aplica a las tablas. A lo largo del libro usamos knitr::kable(), que es perfectamente adecuado para tablas simples (y en el capítulo de visualización dinámica veremos DT para tablas interactivas). Cuando una tabla es una pieza central de un informe, el estándar actual para tablas estáticas con calidad de publicación es la librería gt, desarrollada por el equipo de Posit. 4.22 Exportar gráficos con ggsave

Para guardar un gráfico en un fichero usamos la función ggsave. Esta función guarda, por defecto, el último gráfico generado, o el gráfico que le pasemos como argumento. Soporta múltiples formatos: PNG (para web), PDF (para publicaciones), SVG (vectorial escalable), JPEG, TIFF, entre otros:

# Guardar el último gráfico generado
ggsave("mi_grafico.png", width = 8, height = 5, dpi = 300)

# Guardar en PDF (ideal para publicaciones, escalable sin pérdida)
ggsave("mi_grafico.pdf", width = 8, height = 5)

# Guardar un gráfico almacenado en una variable
p <- ggplot(owid_country, aes(x = gdp_per_capit, y = life_expectancy)) + geom_point()
ggsave("dispersion.png", plot = p, width = 8, height = 5, dpi = 300)

Los parámetros width y height controlan las dimensiones del gráfico en pulgadas y dpi la resolución (300 dpi es estándar para impresión, 72-150 dpi para pantalla). Para presentaciones o informes donde los gráficos se van a ampliar, es recomendable usar formatos vectoriales como PDF o SVG.

Ideas clave del capítulo

Ideas clave

  • Todo ggplot se construye por capas: datos → aes → geom → scale → theme/labs.
  • El tipo de gráfico debe elegirse según la pregunta (comparar, distribución, relación, evolución…); la guía de selección del inicio ayuda a decidir.
  • Los gráficos circulares son difíciles de interpretar con muchas categorías; casi siempre un diagrama de barras comunica mejor.
  • El color debe tener significado; para publicaciones conviene usar escalas accesibles (viridis).
  • Distinguir coord_cartesian (zoom sin eliminar datos) de ylim/scale_..._continuous(limits=) (elimina datos y afecta a las estadísticas).

Errores frecuentes

  • Usar geom_bar() (que cuenta ocurrencias) cuando ya se tienen valores calculados, en lugar de geom_col().
  • Confiar el orden de las barras al alfabético en vez de fijarlo con factor(..., levels=...).
  • Recortar el eje con ylim sin darse cuenta de que se han eliminado datos y cambiado la regresión.
